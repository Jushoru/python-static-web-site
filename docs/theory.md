# T1: сравнение генераторов статических сайтов

## Задача и границы сравнения

Цель — выбрать инструмент для публикации результатов экспериментов: текста,
формул, таблиц, графиков, вычислений и ссылок на источники. Сравниваются
**MkDocs + Material**, **Sphinx + MyST-Parser**, **Pelican** и **Quarto**.
Первые три генератора относятся к экосистеме Python. Quarto рассматривается как
дополнительная система научной публикации с выполнением Python через Jupyter;
его CLI устанавливается отдельно.

Четыре одинаковых сайта для измерения производительности не создавались. Практический эксперимент
[P3](practice.md) выполнен только на MkDocs 1.6.1 с Material 9.7.7.

В основном стеке Sphinx учитывается MyST-Parser для Markdown. Для исполнения
ноутбуков отдельно нужен MyST-NB: один MyST-Parser Python-код не выполняет.
Для других дополнительных возможностей также названы расширения; их наличие
не означает, что они уже установлены в нашем проекте.

**[Матрица с весами, расчёт и диаграмма →](theory-scores.md)**

## Научный контент

### 1. Форматы исходников {#formats}

| Стек | Возможности и ограничения |
| --- | --- |
| MkDocs + Material | Основной формат — Markdown через Python-Markdown. Для `.ipynb` нужен отдельный конвертер или плагин; `.rst`, MyST и `.qmd` нельзя считать штатными входами. |
| Sphinx + MyST | reStructuredText и Markdown с директивами MyST. Ноутбуки `.ipynb` добавляет MyST-NB. |
| Pelican | reStructuredText и Markdown; Markdown требует соответствующей Python-библиотеки. Ноутбуки требуют отдельного обработчика. |
| Quarto | `.qmd` — Markdown с метаданными и вычисляемыми блоками; также поддерживаются `.ipynb`. Это не обработчик всех директив Sphinx. |

Источники: [MkDocs](https://www.mkdocs.org/),
[MyST-Parser](https://myst-parser.readthedocs.io/en/latest/),
[Pelican: контент](https://docs.getpelican.com/en/stable/content.html),
[Quarto: Python](https://quarto.org/docs/computations/python.html).

### 2. Формулы и ссылки на уравнения {#math}

| Стек | Возможности и ограничения |
| --- | --- |
| MkDocs + Material | Документирована связка `pymdownx.arithmatex` с MathJax либо KaTeX. Нумерацию и ссылки нужно настраивать отдельно; Markdown сам их не обеспечивает. |
| Sphinx + MyST | Математические блоки, метки уравнений и ссылки; в MyST есть расширение `amsmath`. HTML может использовать MathJax, LaTeX-вывод обрабатывает формулы средствами TeX. |
| Pelican | Возможен показ формул через разметку и расширения, например `render-math`. Единую систему научных ссылок и нумерации нужно организовывать дополнительно. |
| Quarto | Метки `eq-...`, нумерация и перекрёстные ссылки входят в научную разметку; для HTML предусмотрены разные способы отображения математики, включая MathJax и KaTeX. |

Поддержка LaTeX-синтаксиса в браузере не равна поддержке любого пакета LaTeX.
Для `amsmath` необходимо проверять конкретные окружения и выбранный движок.
Для автономного сайта математический JavaScript и шрифты должны храниться
локально; пример настройки с CDN ещё не доказывает автономность.

Источники: [Material: математика](https://squidfunk.github.io/mkdocs-material/reference/math/),
[MyST: расширения](https://myst-parser.readthedocs.io/en/latest/syntax/optional.html),
[Sphinx: математика](https://www.sphinx-doc.org/en/master/usage/restructuredtext/directives.html#math),
[плагины Pelican](https://github.com/getpelican/pelican-plugins),
[Quarto: HTML-математика](https://quarto.org/docs/output-formats/html-basics.html#latex-math).

### 3. Рисунки, подписи и нумерация {#figures}

| Стек | Возможности и ограничения |
| --- | --- |
| MkDocs + Material | Изображения, подписи через HTML и ссылки по якорям. Сквозная автонумерация рисунков и панелей не является функцией обычного Markdown; нужна дополнительная логика. |
| Sphinx + MyST | Директива `figure`, подписи, метки и `numfig`/`numref`. Группы изображений и отдельные ссылки на подрисунки могут потребовать расширений. |
| Pelican | Изображения и подписи зависят от разметки; для общего счётчика рисунков и подрисунков нужна дополнительная обработка. |
| Quarto | Подписи, метки `fig-...`, перекрёстные ссылки, составные рисунки и подписи к отдельным панелям. |

Легенда внутри графика обычно создаётся библиотекой визуализации, а не SSG.
Источники: [Sphinx: нумерация](https://www.sphinx-doc.org/en/master/usage/configuration.html#confval-numfig),
[Quarto: рисунки](https://quarto.org/docs/authoring/figures-and-layout.html),
[Quarto: ссылки](https://quarto.org/docs/authoring/cross-references.html).

### 4. Сложные и вычисляемые таблицы {#tables}

| Стек | Возможности и ограничения |
| --- | --- |
| MkDocs + Material | Простые Markdown-таблицы. Объединение ячеек — HTML или расширение; CSV/DataFrame можно преобразовать скриптом перед сборкой, как в нашем P3. |
| Sphinx + MyST | `list-table`, `csv-table`, таблицы reStructuredText с объединением ячеек. DataFrame можно вывести через исполняемый ноутбук; переносы длинных таблиц зависят от формата вывода. |
| Pelican | Таблицы Markdown/reStructuredText либо HTML. Для вычисления DataFrame при сборке нужен собственный шаг или плагин. |
| Quarto | Таблицы Markdown и вывод вычислений; поддерживаются сложные таблицы. Объединение ячеек и длинные таблицы нужно проверять отдельно для HTML и PDF. |

Произвольная HTML-таблица не обязана без изменений переходить в PDF. Для всех
стеков следует проверять многостраничные таблицы, повтор заголовков и ширину колонок.
Источники: [Docutils: таблицы и CSV](https://docutils.sourceforge.io/docs/ref/rst/directives.html#tables),
[Quarto: таблицы](https://quarto.org/docs/authoring/tables.html),
[Material: таблицы](https://squidfunk.github.io/mkdocs-material/reference/data-tables/).

### 5. Интерактивные визуализации и размер {#interactive}

Plotly, Bokeh и Altair создают визуализации; SSG отвечает за размещение HTML,
данных и библиотек JavaScript. В MkDocs и Pelican обычно используется отдельный
экспорт графика и его встраивание. Sphinx может подключать результаты через
ноутбуки или специальные расширения. Quarto поддерживает вывод вычислений и
виджеты в составе документа. Внешний HTML можно показывать через `iframe`,
но его пути, размеры и доступность ресурсов нужно проверять.

Для статического хостинга подходят взаимодействия, которые полностью работают
в браузере. График с обратным вызовом Python, требующим сервер Bokeh или Shiny,
нельзя превратить в автономный простым копированием HTML.

| Вариант | Что учитывать в размере |
| --- | --- |
| PNG или SVG | Размер самого файла; для отображения не нужна библиотека графиков |
| HTML с библиотекой с CDN | HTML мал, но первый просмотр дополнительно загружает JavaScript из сети |
| Автономный интерактивный график | HTML/JSON плюс локальная библиотека; общий ресурс можно разделить между несколькими страницами |

Для предоставленного вместе с черновиком примера измерены **9 725 байт
(9,50 КиБ)** у `radar_ssg.html` и **298 997 байт (291,99 КиБ)** у PNG.
В HTML есть внешняя загрузка Plotly: 9,50 КиБ — не полный объём загрузки.
Это проверка двух файлов, а не сравнение эффективности четырёх генераторов.
Полный сетевой объём интерактивного варианта не измерялся.

В итоговом отчёте используется [пересчитанная статическая диаграмма](theory-scores.md):
она читабельна без интерактивности и не требует внешней библиотеки. Размеры её
SVG и PNG приведены рядом с рисунком. Баллы за этот критерий характеризуют
удобство интеграции, **не размер и не скорость**.

Источники: [Plotly: HTML и автономность](https://plotly.com/python/interactive-html-export/),
[Bokeh: встраивание](https://docs.bokeh.org/en/latest/docs/user_guide/output/embed.html),
[Altair: сохранение](https://altair-viz.github.io/user_guide/saving_charts.html),
[Quarto: виджеты Jupyter](https://quarto.org/docs/interactive/widgets/jupyter.html).

### 6. Исполнение кода и кэш {#execution}

| Стек | Возможности и ограничения |
| --- | --- |
| MkDocs + Material | Код в блоке Markdown отображается, но не исполняется. В нашем проекте Python-скрипт запускается хуком; собственный кэш учитывает данные, код и окружение. |
| Sphinx + MyST | MyST-NB исполняет ноутбуки и использует Jupyter Cache. Это отдельное расширение, не функция MyST-Parser. |
| Pelican | Обработка вычислений требует отдельного скрипта либо плагина. Кэш статей генератора нельзя автоматически считать кэшем научных вычислений. |
| Quarto | Выполнение Python через Jupyter и кэш результатов; `freeze` позволяет повторно использовать вычисленный контент при сборке проекта. |

Изменение внешнего CSV не всегда обнаруживается кэшем ноутбука по содержимому
ячеек. Нужно отдельно описать зависимость от данных или принудительное обновление.
Само наличие кэша не гарантирует воспроизводимость: также фиксируются версии
зависимостей, данные, случайное зерно и правила инвалидирования.

Источники: [MyST-NB: выполнение и кэш](https://myst-nb.readthedocs.io/en/latest/computation/execute.html),
[Quarto: управление вычислениями](https://quarto.org/docs/projects/code-execution.html),
[наш конвейер и замеры](build.md).

### 7. Библиография и стили {#bibliography}

| Стек | Возможности и ограничения |
| --- | --- |
| MkDocs + Material | BibTeX не встроен. Пример решения — `mkdocs-bibtex` с Pandoc/CSL; его исходный репозиторий архивирован, поэтому для нового проекта требуется проверка совместимости и сопровождения. |
| Sphinx + MyST | `sphinxcontrib-bibtex`: BibTeX, ссылки и библиография. Стандартные стили основаны на Pybtex; произвольный CSL-файл не следует считать автоматически поддерживаемым. |
| Pelican | Ссылки можно оформить вручную; автоматический BibTeX/CSL требует дополнительного конвейера. |
| Quarto | Bibliography в BibTeX/BibLaTeX и других форматах, обработка цитат и выбор CSL-стиля предусмотрены системой публикации. |

Источники: [mkdocs-bibtex](https://github.com/shyamd/mkdocs-bibtex),
[sphinxcontrib-bibtex](https://sphinxcontrib-bibtex.readthedocs.io/en/latest/usage.html),
[Quarto: цитирование](https://quarto.org/docs/authoring/citations.html).

### 8. Сноски, глоссарий и структура {#structure}

MkDocs поддерживает сноски через расширение Markdown; глоссарий, список
обозначений и нумерацию разделов можно подготовить вручную или расширениями.
У Sphinx есть структурные директивы, `glossary`, ссылки на термины и нумеруемое
оглавление. Pelican использует возможности выбранной разметки, но общий
справочный аппарат сайта нужно организовать отдельно. Quarto поддерживает
сноски и нумерацию разделов; список обозначений можно оформить отдельным
разделом, а автоматический глоссарий требует дополнительного решения.
Поэтому Quarto не получает максимальный балл за этот составной критерий.

Источники: [Python-Markdown: сноски](https://python-markdown.github.io/extensions/footnotes/),
[Sphinx: директивы](https://www.sphinx-doc.org/en/master/usage/restructuredtext/directives.html),
[Quarto: основы Markdown](https://quarto.org/docs/authoring/markdown-basics.html).

## Вёрстка и форматы вывода

### 1. Адаптивные сетки и карточки {#grids}

Material предлагает сетки и карточки. Для Sphinx типовой путь — расширение
`sphinx-design`, в котором число колонок можно задать для разных экранов.
В Pelican сетка определяется темой и пользовательским CSS. Quarto предлагает
колонки, Bootstrap grid и карточки списков документов. Адаптивность нужно
проверять на узком экране, особенно для широких таблиц и встроенных графиков.

Источники: [Material: grids](https://squidfunk.github.io/mkdocs-material/reference/grids/),
[Sphinx Design](https://sphinx-design.readthedocs.io/en/latest/grids.html),
[Quarto: layout](https://quarto.org/docs/output-formats/page-layout.html),
[Quarto: listings](https://quarto.org/docs/websites/website-listings.html).

### 2. Шаблоны страниц {#templates}

| Стек | Примеры страниц и способ изменения |
| --- | --- |
| MkDocs + Material | Документ, главная страница с карточками; Jinja-блоки можно переопределять через каталог `overrides` без копирования всей темы. |
| Sphinx + MyST | Документ, общий индекс, индекс модулей, поиск; HTML-темы и Jinja-шаблоны расширяются отдельно. |
| Pelican | Статья, статическая страница, архив, категория, тег, автор; шаблоны Jinja хорошо соответствуют структуре блога. |
| Quarto | Статья, сайт, книга, список публикаций, презентация; настройки формата, Pandoc-шаблоны и расширения. Это другой механизм, а не Jinja-тема MkDocs. |

Единого честного «числа макетов» нет: тема, шаблон документа и формат вывода —
разные сущности. Поэтому сравниваются перечисленные типовые задачи и механизм
переопределения, а не произвольное количество тем из каталога.

Источники: [Material: overrides](https://squidfunk.github.io/mkdocs-material/customization/),
[Sphinx: шаблоны](https://www.sphinx-doc.org/en/master/development/html_themes/templating.html),
[Pelican: темы](https://docs.getpelican.com/en/stable/themes.html),
[Quarto: форматы](https://quarto.org/docs/output-formats/all-formats.html).

### 3. Один источник, несколько форматов {#outputs}

MkDocs и Pelican прежде всего выпускают HTML-сайты; браузерная печать и сторонний
PDF-плагин не эквивалентны встроенному издательскому конвейеру. Sphinx имеет
строители HTML, LaTeX, EPUB, текстового и других представлений; из LaTeX можно
получить PDF при наличии TeX. Quarto выпускает HTML, PDF, DOCX, EPUB,
презентации и другие форматы. Для PDF также нужны соответствующие средства
рендеринга. Интерактивному графику в печати потребуется статическая замена.

Источники: [строители Sphinx](https://www.sphinx-doc.org/en/master/usage/builders/index.html),
[форматы Quarto](https://quarto.org/docs/output-formats/all-formats.html).

## Эксплуатация

### 1. Версии документации {#versions}

Git хранит историю исходников, но сам по себе не создаёт переключатель версий
на опубликованном сайте. Для MkDocs существует `mike`, для Sphinx —
`sphinx-multiversion`. Для рассматриваемых конфигураций Pelican и Quarto
потребуется самостоятельно собирать версии в разные каталоги и связывать их
навигацией. В этом учебном отчёте пока публикуется одна версия сайта.

Источники: [mike](https://github.com/jimporter/mike),
[sphinx-multiversion](https://github.com/sphinx-contrib/multiversion).

### 2. Локальный поиск и русский язык {#search}

| Стек | Документированная возможность |
| --- | --- |
| MkDocs + Material | Поиск в браузере по локальному индексу, языки `ru` и `en`; языковые стеммеры и стоп-слова Lunr. |
| Sphinx + MyST | Индекс HTML-поиска, `html_search_language = 'ru'`, языковой стеммер. |
| Pelican | В выбранном базовом стеке собственного поиска нет; нужно подключить плагин или отдельную библиотеку. |
| Quarto | Полнотекстовый поиск по локальному индексу; наличие русского морфологического анализа по этой документации не установлено. |

**Стемминг не равен лемматизации и полноценному морфологическому анализу.**
Наличие русских подписей интерфейса тоже ничего не доказывает о качестве поиска.
Сравнительный тест релевантности не проводился. Его можно выполнить на одном
корпусе с запросами «эксперимент/эксперимента/эксперименты», «кэш/кэширование»,
аббревиатурами и словами с «ё», заранее задав ожидаемые страницы. Балл здесь
учитывает документированную поддержку, а не доказанную точность поиска.

Источники: [поиск Material](https://squidfunk.github.io/mkdocs-material/setup/setting-up-site-search/),
[HTML-поиск Sphinx](https://www.sphinx-doc.org/en/master/usage/configuration.html#confval-html_search_language),
[поиск Quarto](https://quarto.org/docs/websites/website-search.html).

### 3. Локализация {#i18n}

В Material `language: ru` переводит элементы интерфейса; переводы содержимого
потребуют отдельных страниц/сборок либо плагина. Sphinx поддерживает извлечение
текстов и каталоги переводов gettext. Pelican связывает переводы статей
метаданными; для отдельных языковых подсайтов и шаблонов нужна дополнительная
настройка. В Quarto `lang` задаёт язык документа и стандартных подписей, но
не переводит авторский текст автоматически.

Источники: [язык Material](https://squidfunk.github.io/mkdocs-material/setup/changing-the-language/),
[Sphinx i18n](https://www.sphinx-doc.org/en/master/usage/advanced/intl.html),
[переводы Pelican](https://docs.getpelican.com/en/stable/settings.html#translations),
[язык Quarto](https://quarto.org/docs/authoring/language.html).

### 4. Автодокументирование кода {#autodoc}

Для MkDocs документацию из docstrings создаёт отдельный `mkdocstrings`.
В Sphinx есть стандартное расширение `autodoc`, связанное с системой ссылок
на программные объекты. Для Pelican нужен дополнительный конвейер генерации
страниц. Для Quarto существует отдельный `quartodoc`. Поэтому для большого
справочника Python API Sphinx остаётся сильным кандидатом: нельзя автоматически
объявлять MkDocs лучшим для любого программного проекта.

Источники: [mkdocstrings](https://mkdocstrings.github.io/),
[Sphinx autodoc](https://www.sphinx-doc.org/en/master/usage/extensions/autodoc.html),
[quartodoc](https://machow.github.io/quartodoc/get-started/overview.html).

### 5. Расширяемость {#extensions}

MkDocs предоставляет плагины и хуки событий сборки. Sphinx — расширения,
директивы и роли. Pelican — плагины и сигналы. Quarto — расширения, фильтры
Lua, shortcodes и шаги проекта. Во всех случаях интеграция возможна, но
добавляет код и зависимости, которые нужно сопровождать. Например, наш
хук MkDocs связывает сборку сайта с подготовкой таблиц и графиков P3.

Источники: [плагины MkDocs](https://www.mkdocs.org/dev-guide/plugins/),
[расширения Sphinx](https://www.sphinx-doc.org/en/master/extdev/index.html),
[плагины Pelican](https://docs.getpelican.com/en/stable/plugins.html),
[расширения Quarto](https://quarto.org/docs/extensions/).

### 6. Время сборки и размер сайта {#performance}

Сравнивать скорость по впечатлениям нельзя: на результат влияют тема, поиск,
объём текста, исполнение кода, прогрев, диск и версии зависимостей.

| Стек | Полная сборка после прогрева, 100 страниц | Инкрементальная сборка | Размер результата |
| --- | ---: | --- | ---: |
| MkDocs 1.6.1 + Material 9.7.7 | 4,231 с, среднее 5 повторов | Не измерялась | 8 958 848 байт |
| Sphinx + MyST | Не измерялась | Не измерялась | Не измерялся |
| Pelican | Не измерялась | Не измерялась | Не измерялся |
| Quarto | Не измерялась | Не измерялась | Не измерялся |

Наш тест удаляет предыдущий результат сборки, но не очищает файловый кэш ОС:
это **полная сборка после прогрева**, а не «холодная ОС». Остальные объёмы,
разброс и конфигурация приведены в [результатах P3](results.md).
[Ускорение подготовки отчёта кэшем](build.md) измеряет другой этап;
оно не является временем инкрементальной сборки MkDocs.

Холодные и инкрементальные замеры всех четырёх систем остаются ограничением
теоретического сравнения. Поэтому этот критерий описан, но не включён в
балльный рейтинг. Для полноценного сравнительного теста нужны одинаковый
корпус, согласованные функции, отдельный сценарий изменения одной страницы
и одинаковые правила измерения размеров и повторов.

### 7. Сопровождение, лицензии и установка {#maintenance}

| Стек | Лицензия основного проекта | Распространение |
| --- | --- | --- |
| MkDocs + Material | MkDocs: BSD-2-Clause; Material: MIT | Python-пакеты `mkdocs`, `mkdocs-material` |
| Sphinx + MyST | Sphinx: BSD-2-Clause; MyST-Parser: MIT | Python-пакеты `sphinx`, `myst-parser` |
| Pelican | AGPL-3.0 | Python-пакет `pelican` |
| Quarto | CLI начиная с 1.4: MIT; у компонентов могут быть другие лицензии | Отдельный дистрибутив CLI; Python/Jupyter устанавливаются для вычислений |

У всех четырёх проектов есть открытые исходники, документация и история выпусков.
В рейтинге это общий базовый уровень, а не утверждение об одинаковой активности.
Число релизов, скорость исправления ошибок и доступность каждого плагина
сравнительно не измерялись. Зависимости и расширения нужно проверять отдельно:
например, архивирование `mkdocs-bibtex` показывает, почему зрелость генератора
не гарантирует сопровождение всех его плагинов.

Для Python-пакетов возможно использование зеркала индекса через настройки pip,
если на нём есть нужные версии и зависимости. Их наличие на конкретном
отечественном зеркале в этой работе **не проверялось**. Установка Python-пакета
с похожим названием не заменяет установку Quarto CLI. Для CI необходимо
зафиксировать версии и проверить загрузку на выбранном исполнителе.

Источники лицензий и выпусков: [MkDocs](https://github.com/mkdocs/mkdocs),
[Material](https://github.com/squidfunk/mkdocs-material),
[Sphinx](https://github.com/sphinx-doc/sphinx/blob/master/LICENSE.rst),
[MyST-Parser](https://github.com/executablebooks/MyST-Parser),
[Pelican](https://github.com/getpelican/pelican),
[Quarto](https://quarto.org/license.html).
Механизм выбора индекса: [документация pip](https://pip.pypa.io/en/stable/cli/pip_install/#index-url).
Эта таблица описывает инструменты; выбор лицензий нашего кода и текста отчёта
оформляется отдельно.

## Вывод и условия изменения выбора {#conclusion}

Для сценария **вычисления → научный текст → HTML и печатный документ**
[принятая модель](theory-scores.md) отдаёт предпочтение **Quarto**.
Причина — сочетание исполнения кода, ссылок, библиографии и разных форматов
вывода. Это вывод из выбранных требований и экспертных оценок; он не доказывает
превосходство по скорости или всем возможным задачам.

| Если главное требование меняется… | Что стоит выбрать или проверить |
| --- | --- |
| Большой справочник Python API, ссылки на программные объекты, переводы | Sphinx + MyST; повысить веса autodoc, структуры и i18n |
| Небольшой HTML-отчёт с готовыми графиками и удобной навигацией | MkDocs + Material; выполнение анализа можно оставить внешнему скрипту |
| Публикации по датам, авторы, теги, архив и RSS | Pelican; низкий балл в научной модели не означает плохой блоговый генератор |
| Ноутбуки, вычисляемые таблицы и несколько форматов публикации | Quarto; проверить переносимость интерактивных элементов в PDF |
| Решающее значение имеют скорость, объём или конкретная среда установки | Провести сопоставимые замеры: текущая модель не даёт ответа |

**Почему сам отчёт сделан на MkDocs?** Это выбранный инструмент практической
части задания. Для нашего отчёта достаточно Markdown, локальных рисунков,
поиска и Python-скрипта подготовки результатов. Теоретическое предпочтение
Quarto в более широком научном сценарии не требует переносить готовую практику
на другой генератор.

Раздел T1 содержит документальный обзор и прозрачную модель решения. Его
ограничения — отсутствие общего теста четырёх инструментов, проверки каждого
плагина в одной среде и сравнительного теста русского поиска. Реальные
измерения MkDocs и кэша приведены отдельно и не подменяются экспертными баллами.

# Отладка

В этом разделе фиксируются реальные проблемы, возникшие при разработке,
проверенные гипотезы и способы устранения. Предупреждение Material о будущей
версии MkDocs 2.0 не считается ошибкой нашего проекта: сборка с MkDocs 1.6.1
завершается успешно.

## Неверное отображение русского текста в скачиваемом Markdown

### Проявление ошибки

При открытии ссылки на исходный Markdown тестовой страницы браузер показывал
неправильные символы вместо русского текста. Например, заголовок
`# Страница 1` отображался так:

```text
# Ð¡Ñ‚Ñ€Ð°Ð½Ð¸Ñ†Ð° 1
```

Сама HTML-страница с примером отображалась правильно. Ошибка проявлялась при
открытии файла `downloads/example-page.md.txt`. Сообщения об исключении Python
не было: проблема была видна в содержимом страницы браузера.

### Гипотеза

Браузер неправильно определяет кодировку отдельного текстового файла.
Его содержимое записано в UTF-8, но сервер не сообщает эту кодировку явно.

### Проверка

1. Прочитали файл с явным декодированием UTF-8: русский текст оказался корректным.
2. Проверили HTTP-ответ локального сервера: статус `200`, заголовок
   `Content-Type: text/plain` без параметра `charset`.
3. Сравнили исходный Markdown и скачиваемый пример после декодирования и
   нормализации переводов строк: содержимое совпало.

Таким образом, проблема возникла при определении кодировки отображения,
а не при генерации русского текста или сборке Markdown в HTML.

### Решение

В функции `example_page()` скрипта `scripts/prepare_report.py` изменили запись
скачиваемого текстового файла: передаём байты UTF-8 с меткой BOM.

```python
write_if_changed(
    DOCS / "downloads" / "example-page.md.txt",
    sample.encode("utf-8-sig"),
)
```

Метка BOM — байты `EF BB BF` в начале файла — позволяет браузеру определить UTF-8,
даже если сервер не передал кодировку в HTTP-заголовке. Содержимое Markdown
при этом сохраняется. Правка сделана в генераторе, поэтому действует и после
последующих сборок.

### Результат проверки

- Строгая сборка `python -m mkdocs build --strict` завершилась успешно.
- В файле, полученном по HTTP, присутствует метка UTF-8 BOM.
- Текст примера совпадает с исходной тестовой страницей после декодирования
  и нормализации переводов строк.
- После обновления файла пользователь подтвердил корректное скачивание
  и отображение русского текста.
